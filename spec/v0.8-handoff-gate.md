# APMF V0.8 Handoff Gate

Status: experimental. V0.8 adds an operational health gate that composes existing checks without changing canonical memory semantics.

## `doctor.sh`

`scripts/doctor.sh [--strict] <project>` MUST be read-only and MUST:

- run `validate.sh`, `check-references.sh`, and `close-provenance.sh --check`;
- report Git HEAD, NOW branch alignment, blockers, active-task counts, and worktree state;
- inspect optional retrieval metadata read-only when `.ai/index/memory.sqlite3` exists;
- treat missing or stale optional retrieval as a warning by default;
- return non-zero for canonical validation/reference/provenance errors;
- make warnings non-zero under `--strict`.

The doctor MUST NOT close provenance, rebuild retrieval indexes, archive changes, edit Markdown, or contact remote services.

## Checkpoint composition

`checkpoint.sh` MAY close unresolved provenance as its existing explicit write step. After that step it MUST run the doctor and fail when the doctor reports a canonical error. This preserves the boundary between an intentional provenance mutation and read-only diagnosis.

## End-to-end contract

The compatibility test MUST exercise init, first commit, provenance closeout, active change creation, checkpoint, route failure, lifecycle archive, retrieval rebuild, and strict final handoff. Optional retrieval remains optional for ordinary projects; strict release gates may require it.
