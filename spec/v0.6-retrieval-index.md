# APMF V0.6 Retrieval Index

Status: experimental and optional. V0.6 adds a derived local search accelerator; it does not change the canonical Markdown protocol.

## Source of truth

The only authoritative memory remains Git-tracked Markdown under `.ai/`. The retrieval database at `.ai/index/memory.sqlite3` is disposable, ignored by Git, and MUST never be used to write or replace canonical files. Agents MUST still bootstrap from `AGENTS.md`, `.ai/NOW.md`, and `.ai/INDEX.md`.

## Build contract

`scripts/index-memory.sh <project>` MUST:

- discover sorted UTF-8 Markdown files beneath `.ai/**/*.md`, including active changes and archives, while excluding `.ai/index/`;
- build a SQLite FTS5 database containing relative paths and document content;
- write through a temporary database and atomically replace the derived destination only after a successful commit;
- record schema version, source pattern, document count, and the Git `HEAD` used for the build;
- leave canonical Markdown untouched and fail without replacing an existing index when the build cannot complete.

The helper MAY require Python with SQLite FTS5 support. Projects without that optional dependency continue to use filesystem and INDEX routing normally.

## Query contract

`scripts/index-memory.sh --query <fts-query> [--limit <n>] <project>` MUST open the existing database read-only, use FTS5 `MATCH` and `bm25()` ranking, and print repository-relative path, score, and a bounded snippet as tab-separated fields. A missing database or malformed query MUST fail clearly without writing files.

## Rebuild and staleness

Rebuild is the only supported write operation. It MUST remove documents deleted from canonical Markdown and include newly added or changed documents. Incremental updates, embeddings, MCP servers, cloud indexes, and agent-specific adapters are outside V0.6.
