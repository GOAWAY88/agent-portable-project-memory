# APMF V0.4: Provenance Closeout

Status: experimental. V0.4 adds a mechanical handoff helper; it does not change canonical Markdown, status vocabularies, or the frozen V0.1-alpha contract.

## Problem

Freshly initialized projects intentionally contain `verified_at_commit: unknown`, because no Git commit exists yet. After the first commit, leaving those placeholders in NOW, knowledge, or ADR metadata weakens provenance and requires repetitive manual editing.

## Contract

`scripts/close-provenance.sh <project>` MUST:

- require a Git work tree and an existing `HEAD` commit;
- inspect only `.ai/NOW.md`, `.ai/knowledge/*.md`, and `.ai/decisions/*.md` except the instructional `ADR-TEMPLATE.md`;
- replace only front-matter values `unknown`, `null`, `none`, or `[commit]` on `verified_at_commit` with the full `HEAD` commit SHA;
- never overwrite an existing non-placeholder commit value;
- leave content outside that front-matter field unchanged;
- be idempotent on a second run.

With `--check`, the helper MUST make no writes and exit non-zero when any supported file still has an unresolved placeholder.

An unborn repository MUST fail without changing files. The helper MUST NOT modify archived history, evidence prose, task status, or semantic knowledge content; agents remain responsible for verifying the claims represented by the metadata.

`scripts/checkpoint.sh` SHOULD invoke the helper for initialized APMF projects so the normal handoff path closes mechanical provenance automatically. A failed closeout MUST make the checkpoint fail rather than silently claim a complete handoff.

## Rationale and boundary

Binding metadata to the current commit is deterministic and safe to automate. Deciding whether a claim is still true, whether `updated` should change, or whether evidence is sufficient remains semantic work and is not automated by this feature.
