# APMF V0.2: Memory Integrity

Status: experimental. V0.2 extends V0.1; it does not change the canonical Markdown model.

## Integrity requirements

An APMF V0.2 validator MUST fail when:

- `NOW.md` omits required fields or names a non-existent active change;
- `INDEX.md` points to a missing local file/directory;
- knowledge or ADR status is outside its defined vocabulary;
- an ADR filename, id, heading, required provenance field, or accepted evidence is malformed;
- a supplied `verified_at_commit` cannot be resolved in the repository;
- an active change lacks its four artifacts, required headings, task statuses, evidence content, or branch/commit provenance;
- a completed change (all task statuses `DONE`) remains in `.ai/changes/` instead of being archived;
- a derived runtime/index database is Git-tracked.

The validator MAY accept explicit template placeholders (`YYYY-MM-DD`, `unknown`, and `[active-change]`) in an uninitialized template. A real project SHOULD replace them before claiming verified project memory.

## Status vocabularies

Knowledge documents use `current`, `draft`, `deprecated`, or `superseded`. ADRs use `proposed`, `accepted`, `rejected`, `deprecated`, or `superseded`. Tasks use `TODO`, `IN_PROGRESS`, `BLOCKED`, or `DONE`. An accepted ADR MUST name non-empty evidence.

## Provenance and staleness

Durable knowledge and NOW MUST include `updated` and `verified_at_commit`; ADRs additionally include `created`, `supersedes`, `superseded_by`, and `evidence`. A historical commit remains valid evidence if it resolves locally; V0.2 does not pretend that every historical claim must refer to `HEAD`. Agents SHOULD re-verify high-impact claims when the branch or relevant source changes.

## Compatibility and retrieval boundary

The V0.1-alpha contract is frozen in [`baselines/v0.1-alpha.md`](baselines/v0.1-alpha.md) and tested in CI. SQLite FTS5/BM25, MCP, semantic retrieval, and agent adapters remain later derived layers and MUST NOT become canonical truth in V0.2.
