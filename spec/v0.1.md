# APMF V0.1 specification

Status: experimental. Normative terms MUST, MUST NOT, SHOULD, and MAY are intentional.

## Compatibility minimum

An APMF V0.1-compatible project MUST provide:

- a concise `AGENTS.md` routing/entry protocol;
- `.ai/NOW.md` and `.ai/INDEX.md`;
- `.ai/knowledge/`, `.ai/decisions/`, `.ai/changes/`, and `.ai/archive/`;
- at least one active change with `proposal.md`, `design.md`, `tasks.md`, and `evidence.md`;
- documented authority and lifecycle rules;
- a safe, human-driven checkpoint workflow.

Canonical memory MUST be portable, human-readable, and Git-trackable. Projects MUST NOT require a database, network service, LLM, or agent-specific hook. Derived indexes MAY exist, but MUST be rebuildable and ignored by Git.

`NOW.md` MUST remain bounded and MUST identify current milestone, active change, task, blockers, next action, and verification context. `INDEX.md` MUST route to files rather than duplicate their contents. Archives MUST NOT be part of default bootstrap.

Durable claims SHOULD carry provenance and status. Agents MUST treat executable evidence and current source/configuration as higher authority than memory summaries, and MUST NOT intentionally store secrets.

## Lifecycle and changes

Implementations MUST support the lifecycle in [`../docs/memory-lifecycle.md`](../docs/memory-lifecycle.md). Active changes use the four artifacts defined by [`memory-schema.md`](memory-schema.md); completed changes SHOULD be archived after durable results are promoted.
